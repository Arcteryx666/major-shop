# 👑 MAJOR SHOP

Telegram-магазин: бот + Mini App + админ-панель прямо в Telegram.
Клиент смотрит каталог, сохраняет избранное, оформляет заказ или пишет менеджеру с готовым сообщением.
Администратор добавляет товары, ведёт заказы, промокоды, бонусы и рассылки — не выходя из бота.

## 1. Возможности

**Бот (клиент):** главное меню 👑 MAJOR SHOP с кнопками 🛍 Открыть магазин, 🔥 Новинки, 🏆 Продано, ❤️ Избранное, 🛒 Корзина, 📦 Мои заказы, ⭐ Отзывы, 👤 Профиль, 💬 Связаться с менеджером. Команды `/start /shop /catalog /new /sold /favorites /cart /orders /reviews /contact /help`. Ссылка из QR-кода товара открывает карточку товара. Уведомления: статус заказа, трек-номер, новинки, поступление, снижение цены.

**Mini App:** главная (поиск, категории, баннеры, новинки, популярное, скидки, недавно просмотренные, рекомендации), каталог с поиском, фильтрами (цена, размер, бренд, категория, цвет, состояние, наличие, скидка) и сортировкой, страницы «Новинки», «Продано», «Скидки», «Под заказ», карточка товара (галерея, размеры с остатком, характеристики, доставка), избранное, корзина с промокодом и бонусами, заказы с таймлайном и трек-номером, профиль, настройки уведомлений, бонусы, отзывы. Светлая и тёмная тема Telegram, скелетоны загрузки, потянуть-чтобы-обновить, бесконечная лента, системная кнопка «Назад».

**Кнопки товара:** 🛒 В корзину · 💬 Хочу купить (открывает чат менеджера с текстом «Привет! Хочу приобрести: Товар / Размер / Количество / Цена») · ❓ Задать вопрос (редактируемый текст) · 🔵 Заказать (для товаров под заказ) · 🔔 Сообщить о поступлении (для проданных). В разделе «Продано» кнопок покупки нет.

**Админ-панель в боте (`/admin`):** 🛍 Товары (фильтры по статусу, поиск, категории, мастер добавления из 15 шагов, редактирование любого поля, скидка, возврат в продажу, под заказ, «продано», архив, QR-код) · 📦 Заказы (🟡 бронь 30 мин / 1 ч / 3 ч / 12 ч / 24 ч / своё время, ⚙️ в обработку, 🔵 под заказ, 📦 отправка с трек-номером, ✅ клиент получил, 🏁 завершить, ❌ отмена с причиной) · ⭐ Отзывы (модерация, ответ) · 🎟 Промокоды · 💎 Бонусы · 📢 Рассылка («Отправить N пользователям? ✅ Да») · 👥 Клиенты · 📊 Статистика · ⚙️ Настройки.

**Бизнес-правила** (проверяются на сервере и покрыты тестами):

- товар нельзя продать дважды: остаток списывается атомарно, остаток не бывает отрицательным (ограничение в БД);
- новый заказ удерживает товар; бронь истекает автоматически → заказ отменяется, товар возвращается в продажу, клиент получает уведомление;
- неподтверждённый новый заказ освобождает товар через `newOrderHoldHours` (по умолчанию 48 ч);
- предзаказ не уменьшает склад и не смешивается с товарами в наличии;
- отменённый заказ нельзя отправить, доставленный — вернуть в «Новый», отправленный — отменить;
- бонусы начисляются только за завершённый заказ и ровно один раз; при отмене списанные бонусы и промокод возвращаются;
- промокод: срок, общий лимит, лимит на клиента, минимальная сумма; гонка двух заказов не превысит лимит;
- все суммы считает сервер, фронтенду не доверяем.

## 2. Архитектура

```
Telegram ──webhook──► ┌──────────────────────────────┐
                      │ Node.js (один процесс)        │
Mini App (React) ───► │  Fastify API  /api/*          │──► PostgreSQL
  той же ссылкой      │  grammY бот   /telegram/webhook│
                      │  Планировщик (брони, бонусы…) │
                      │  Статика Mini App + SPA        │
                      └──────────────────────────────┘
```

- **Backend:** Node.js 20.19+ (или 22.12+), TypeScript, Fastify 5, grammY, Prisma 6 (без Rust-движка, через `@prisma/adapter-pg`), Zod.
- **Mini App:** React 18, Vite, React Router. Отдаётся тем же сервером → один адрес, без CORS.
- **Фото товаров** хранятся в Telegram (админ присылает фото боту), сервер отдаёт их через `/api/media/:fileId` с кэшем. Отдельное хранилище не нужно.
- **Роли процесса** (`ROLE`): `all` — всё в одном (рекомендуется); `api` + `worker` — если нужно разнести. Фоновые задачи защищены advisory-lock PostgreSQL, поэтому несколько копий не выполнят их дважды.
- **Деньги** хранятся в центах (Int). 1 бонусный балл = 1 единица валюты.

## 4. Требования

- Node.js **20.19+** или **22.12+** и npm 10;
- PostgreSQL **14+** (рекомендуется 16);
- для продакшена — публичный **https**-адрес (Render даёт его автоматически);
- для бэкапов — `pg_dump` / `pg_restore` (пакет `postgresql-client`).

## 5. Создание бота в BotFather

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot` → имя (например, *MAJOR SHOP*) → username (например, `major_shop_bot`).
2. Скопируйте токен вида `123456789:AA…` — это `BOT_TOKEN`. Никому его не показывайте.
3. Рекомендуется: `/setdescription`, `/setabouttext`, `/setuserpic` (логотип).
4. Команды и кнопку меню бот настраивает сам при запуске.

## 6. Как узнать свой Telegram ID

Напишите [@userinfobot](https://t.me/userinfobot) — он пришлёт числовой ID. Это `ADMIN_TELEGRAM_ID`. Администраторов можно указать несколько через запятую: `111,222`.

## 7. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните.

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от BotFather |
| `DATABASE_URL` | да | `postgresql://user:pass@host:5432/db` (на Vercel подходит и `POSTGRES_URL` от интеграции) |
| `ADMIN_TELEGRAM_ID` | да | числовой ID администратора (через запятую — несколько) |
| `MANAGER_USERNAME` | нет | username менеджера без `@`; можно поменять в ⚙️ Настройках бота |
| `MINI_APP_URL` | да* | https-адрес магазина. *На Vercel и Render можно не задавать — берётся адрес проекта |
| `PORT` | нет | по умолчанию 3000 |
| `NODE_ENV` | нет | `production` / `development` |
| `BOT_MODE` | нет | `webhook` (сервер) или `polling` (локально, по умолчанию) |
| `WEBHOOK_SECRET` | нет | секрет webhook; если не задан — выводится из токена бота |
| `PUBLIC_URL` | нет | адрес для webhook, если отличается от `MINI_APP_URL` |
| `ROLE` | нет | `all` / `api` / `worker` |
| `CORS_ORIGINS` | нет | только если Mini App на другом домене |
| `INIT_DATA_MAX_AGE` | нет | срок жизни подписи Mini App, сек (86400) |
| `CRON_SECRET` | нет | ключ для `/api/cron` (Vercel передаёт его сам; для внешнего cron — `?key=`) |
| `DB_POOL_MAX` | нет | размер пула соединений (по умолчанию 10, на Vercel 3) |

Сервер проверяет переменные при старте и пишет, какая неверна (значения в лог не попадают).

## 8. Локальный запуск

```bash
npm install
cp .env.example .env          # заполните BOT_TOKEN, ADMIN_TELEGRAM_ID, DATABASE_URL
# в .env для локальной работы: BOT_MODE=polling, NODE_ENV=development

docker compose up -d postgres # или свой PostgreSQL
npm run db:migrate            # создаёт таблицы
npm run db:seed               # настройки и базовые категории

npm run dev:server            # API + бот (polling) + планировщик на :3000
npm run dev:web               # Mini App на :5173 (API проксируется на :3000)
```

Продакшен-сборка локально:

```bash
npm run build                 # собирает Mini App и сервер
npm start                     # сервер сам раздаёт apps/web/dist
```

## 9. База данных и миграции

- Применить миграции: `npm run db:migrate` (`prisma migrate deploy`). В Docker и на Render миграции применяются автоматически при каждом старте — только новые.
- Изменили `schema.prisma` → создайте миграцию: `npm run db:migrate:dev -- --name описание`.
- Миграции лежат в `apps/server/prisma/migrations`. Вторая миграция (`constraints`) добавляет проверки на уровне БД (остаток ≥ 0, баланс ≥ 0, рейтинг 1–5), индексы поиска `pg_trgm` и строку настроек магазина.

> ⚠️ SQL первых миграций написан вручную по схеме. Перед первым деплоем один раз выполните на пустой локальной базе
> `cd apps/server && npx prisma migrate dev` — Prisma сообщит, если есть расхождения, и предложит догоняющую миграцию.

## 10. Начальные данные

`npm run db:seed` создаёт строку настроек магазина и категории «Одежда», «Обувь», «Аксессуары», «Сумки». Запускать повторно безопасно. Демо-товаров нет: фото хранятся в Telegram, поэтому первые товары добавляются через бота (раздел 17).

## 11. Mini App при локальной разработке

Telegram открывает Mini App только по **https**. Варианты:

- **Туннель:** `cloudflared tunnel --url http://localhost:3000` (или `ngrok http 3000`), полученный адрес — в `MINI_APP_URL`. Перед этим выполните `npm run build -w @major/web`, чтобы сервер раздавал свежий фронтенд.
- **Браузер без Telegram:** каталог и товары работают сразу на `http://localhost:5173`. Для личных разделов (корзина, заказы) передайте подписанный initData: `http://localhost:5173/?tma=<initData>`. Строку можно получить в консоли Telegram Desktop (`Telegram.WebApp.initData`) или сгенерировать тестовую функцией `signInitData` из `apps/server/src/lib/telegram-auth.ts`.

## 12. Подключение Mini App в BotFather

Кнопку меню «🛍 Магазин» бот выставляет сам при старте, если `MINI_APP_URL` начинается с `https://`. Дополнительно (рекомендуется):

1. BotFather → `/mybots` → ваш бот → **Bot Settings → Configure Mini App → Enable Mini App** → укажите `MINI_APP_URL`. Тогда появится ссылка `https://t.me/<bot>?startapp` и кнопка «Открыть» в профиле бота.
2. Поддерживаемые параметры ссылки: `?startapp=p_<slug>` — товар, `o_<id>` — заказ, `new`, `sold`, `cart`, `favorites`, `orders`, `catalog`.
3. Если используете `/setmenubutton` вручную — укажите тот же адрес.

## 13. Docker

```bash
cp .env.example .env              # заполните; BOT_MODE=polling для локального Docker
docker compose up -d --build      # postgres + app
docker compose logs -f app
docker compose exec app node dist/seed.js     # настройки и базовые категории
```

- Фронтенд в режиме горячей перезагрузки: `docker compose --profile dev up web` (порт 5173).
- Данные БД — в томе `pgdata`.

## 14. Деплой на Vercel или Render

### Vercel

Проект собирается для Vercel без ручной настройки: `vercel.json` запускает `npm run build:vercel`, который собирает Mini App (раздаёт CDN Vercel), серверную функцию (API + webhook бота + cron) и применяет миграции БД.

1. **Репозиторий.** В корне репозитория должны лежать `package.json`, `vercel.json`, папки `apps/`, `packages/`, `scripts/`. Если при загрузке на GitHub всё оказалось внутри папки `major-shop/`, укажите её в Vercel → Settings → Build and Deployment → **Root Directory**. Загрузка через веб-интерфейс GitHub берёт не больше 100 файлов за раз — проверьте, что загрузилось всё (сборка сама сообщит, каких файлов не хватает).
2. **База данных.** Vercel → проект → **Storage → Create Database → Neon (Postgres)** → Connect to project. Переменные `DATABASE_URL` и другие подставятся автоматически. Регион базы выберите рядом с регионом функций (например, Frankfurt).
3. **Переменные** (Settings → Environment Variables):
   - `BOT_TOKEN` — токен от @BotFather;
   - `ADMIN_TELEGRAM_ID` — ваш числовой ID;
   - `MANAGER_USERNAME` — username менеджера без @;
   - `CRON_SECRET` — любая случайная строка (рекомендуется).
   `MINI_APP_URL`, `BOT_MODE` и `WEBHOOK_SECRET` задавать не нужно: адрес берётся из домена проекта, режим — webhook, секрет выводится из токена.
4. **Redeploy** (Deployments → ⋯ → Redeploy). В логе сборки должны быть шаги «Применение миграций БД» и «✅ Готово».
5. **Проверка:** откройте `https://<проект>.vercel.app/health` → `{"ok":true}`. Если видите `INIT_FAILED`, в сообщении написано, какой переменной не хватает. Затем напишите боту `/start` — webhook выставляется автоматически при первом обращении к сайту.
6. **Своя частота задач.** Бесплатный Vercel Cron запускает `/api/cron` раз в сутки, а остальное время задачи (истечение броней, рассылки и т. д.) выполняются попутно с запросами к магазину — не чаще раза в минуту. Чтобы брони снимались точно в срок даже без посетителей, создайте бесплатное задание на [cron-job.org](https://cron-job.org): адрес `https://<проект>.vercel.app/api/cron?key=<CRON_SECRET>`, каждую минуту.

Ограничения Vercel: функция живёт до 60 секунд (`FUNCTION_MAX_DURATION`), поэтому большие рассылки отправляются частями и продолжаются автоматически при следующем запуске задач. Тариф Hobby по правилам Vercel — для некоммерческих проектов; для работающего магазина нужен Pro, либо используйте Render.

### Render (24/7)

**Вариант A — Blueprint (рекомендуется):**

1. Загрузите проект в GitHub.
2. Render → **New → Blueprint** → выберите репозиторий. Создадутся web-сервис `major-shop` (Docker) и PostgreSQL `major-shop-db`; `DATABASE_URL` и `WEBHOOK_SECRET` подставятся сами.
3. Заполните `BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, `MANAGER_USERNAME`. `MINI_APP_URL` можно оставить пустым — будет использован адрес сервиса (`https://major-shop.onrender.com`); если подключаете свой домен — укажите его.
4. Дождитесь деплоя. Проверка: `https://<адрес>/health` → `{"ok":true}`.

**Вариант B — вручную:** New → Web Service → Docker, Health Check Path `/health`, переменные из раздела 7 с `BOT_MODE=webhook`; отдельно создайте PostgreSQL и скопируйте Internal Database URL в `DATABASE_URL`.

**Важно для 24/7:** бесплатный web-сервис Render засыпает без трафика и не принимает webhook мгновенно — используйте план **Starter** или выше. Бесплатная БД Render удаляется через 30 дней — для магазина нужен платный план БД. Отдельный worker не нужен: планировщик работает в том же процессе (`ROLE=all`).

## 15. Webhook

При `BOT_MODE=webhook` сервер при каждом запуске сам вызывает `setWebhook` на `PUBLIC_URL/telegram/webhook` (или `MINI_APP_URL/...`) с секретом `WEBHOOK_SECRET`. Запросы без правильного заголовка `X-Telegram-Bot-Api-Secret-Token` отклоняются.

Проверить: `https://api.telegram.org/bot<TOKEN>/getWebhookInfo` — должен быть ваш адрес и `pending_update_count` около нуля.
Вернуться на polling (локально): `BOT_MODE=polling` — webhook удаляется автоматически.

## 16. Первый запуск

1. Откройте бота и отправьте `/start` **с аккаунта администратора** — появится главное меню и кнопка «⚙️ Админ-панель».
2. Отправьте `/admin` → ⚙️ Настройки: название, описание, username менеджера, доставка, контакты, валюта, приветствие, правила, бонусная система.
3. 🛍 Товары → 🗂 Категории: проверьте категории.
4. Добавьте первый товар (раздел 17) и откройте магазин кнопкой «🛍 Магазин».
5. Сделайте тестовый заказ с другого аккаунта и проведите его по статусам.

## 17. Как добавить первый товар

`/admin` → 🛍 Товары → ➕ Добавить товар. Мастер из 15 шагов, на каждом есть ⬅️ Назад, ⏭ Пропустить (для необязательных полей) и ❌ Отмена:

1. Фото — до 10, можно альбомом → «✅ Готово»
2. Название
3. Описание
4. Категория (выбрать или написать новую)
5. Бренд
6. Цена (`120` или `99,90`)
7. Старая цена — для скидки
8. Размеры и остаток: `S:1, M:2` или просто `1`
9. Цвет
10. Материал
11. Состояние
12. Характеристики: по строке «Название: значение»
13. Новинка — да или нет (подписчики получат уведомление)
14. Под заказ: «Нет» или срок `7-14 комментарий`
15. Предпросмотр → ✅ Опубликовать / 💾 В черновики / ✏️ Изменить любое поле

Карточка товара в боте: ✏️ Изменить, 📱 QR-код (ведёт на товар через бота), 🏷 Скидка (цена или `20%`, с датой окончания — снимется автоматически), 🔄 Вернуть в продажу (подписчики получат уведомление), 🔵 Под заказ, 🔴 Продано, 📦 В архив.

## 18. Работа с заказами

Новый заказ приходит администратору сообщением с кнопками:

- 🟡 **Забронировать** — 30 мин / 1 ч / 3 ч / 12 ч / 24 ч / ✍️ своё (`45`, `2ч`, `1д 6ч`). По истечении бронь снимается, товар возвращается в продажу.
- ⚙️ **В обработку** — товар продан, бронь больше не истекает.
- 🔵 **Под заказ** → 📦 Товар получен.
- 📦 **Отправить** — способ доставки, трек-номер, ссылка отслеживания. Клиент получит всё в Telegram.
- ✅ **Клиент получил** → 🏁 **Завершить** — начисляются бонусы. Через `autoCompleteDays` (3 дня) после доставки заказ завершается автоматически.
- ❌ **Отменить** — с причиной для клиента. Остаток, промокод и бонусы возвращаются.

Статусы: 🕐 Создан → 🟡 Забронирован / 🔵 Под заказ → ⚙️ Обрабатывается → 📦 Отправлен → ✅ Доставлен → 🏁 Завершён, либо ❌ Отменён. История изменений хранится.

## 19. Промокоды, бонусы, рассылки, отзывы

- **🎟 Промокоды:** процент или сумма, минимальная сумма заказа, общий лимит, лимит на клиента, срок действия; вкл/выкл, статистика использования.
- **💎 Бонусы:** % начисления, максимум оплаты баллами (% заказа), минимум для списания, срок действия баллов (сгорают автоматически), ручное начисление или списание клиенту.
- **📢 Рассылка:** текст или фото с подписью (форматирование сохраняется), кнопка «Открыть магазин» / товар / своя ссылка, тестовая отправка себе, подтверждение «Отправить N пользователям?». Рассылка идёт с учётом лимитов Telegram, продолжается после перезапуска сервера и присылает отчёт. Получатели — те, кто не заблокировал бота и не отключил уведомления.
- **⭐ Отзывы:** клиент оставляет отзыв после получения заказа; в магазине он появляется только после модерации (✅ / 🚫, можно ответить).

## 20. Настройки магазина

`/admin` → ⚙️ Настройки. Меняются без перезапуска: название, описание, менеджер, доставка, контакты, валюта (EUR, USD, RUB…), приветствие (`{name}` — имя клиента), «О магазине», правила, параметры бонусов, время удержания нового заказа, автозавершение, уведомления о новинках, поступлениях и скидках.
Секреты (токен, ID администратора, доступ к БД) через бота изменить нельзя — только в переменных окружения.

## 21. Тесты

Нужна отдельная тестовая база PostgreSQL (её содержимое очищается).

```bash
createdb major_test
export TEST_DATABASE_URL=postgresql://major:major@localhost:5432/major_test
DATABASE_URL=$TEST_DATABASE_URL npm run test:prepare -w @major/server   # миграции

```

51 тест, Telegram API подменяется:

- **Модульные:** подпись initData, расчёт цены, промокоды и бонусы, переходы статусов, разбор ввода администратора.
- **API:**
  - авторизация и права администратора, rate limit;
  - товары: CRUD, публикация, поиск, фильтры, сортировка;
  - избранное, корзина, размеры;
  - защита от продажи последней вещи двум покупателям;
  - бронь и её истечение, автоотмена, полный цикл заказа, автозавершение;
  - предзаказ, «Продано» и возврат в продажу с уведомлениями;
  - снижение цены, скидка со сроком;
  - промокоды, бонусы, отзывы и модерация, рассылка, статистика, настройки;
  - /api/cron и защита рассылки от двойной отправки несколькими инстансами.
- **Бот:** меню, deep link товара, отказ не-администратору, мастер товара (назад, пропуск, правка из превью, публикация), отмена, бронь со своим сроком, отправка с трек-номером, все разделы админки.

Проверка типов: `npm run typecheck`.

## 22. Резервное копирование и восстановление

```bash
npm run backup                                   # → backups/major-shop-YYYYMMDD-HHMMSS.dump
KEEP_DAYS=14 npm run backup                      # копии старше 14 дней удаляются
npm run restore -- backups/major-shop-….dump     # спросит подтверждение "yes"
```

- Для Docker: `docker compose exec -T postgres pg_dump -U major -Fc major_shop > backups/manual.dump`.
- Автоматически: cron на любом сервере, например `0 4 * * * cd /opt/major-shop && npm run backup`.
- На Render у платных БД есть ежедневные снимки (Dashboard → база → Recovery).
- Перед восстановлением остановите приложение. После запуска миграции применятся автоматически.

## 23. Безопасность

- Mini App авторизуется только по подписи Telegram `initData` (HMAC-SHA256 от токена бота) со сроком действия; Telegram ID из фронтенда без подписи не принимается.
- Права администратора проверяются на сервере по `ADMIN_TELEGRAM_ID` — и в API, и в каждом обработчике бота.
- Webhook защищён секретным заголовком. Токен бота маскируется в логах.
- Ограничение частоты запросов по пользователю Telegram (оформление заказа — 10 в минуту, промокоды — 20 в минуту).
- Все входные данные проверяются Zod; цены, скидки и бонусы считаются только на сервере.
- Остатки и балансы защищены ограничениями CHECK в БД; смена статусов — с оптимистичной блокировкой.
- Храним о клиенте только Telegram ID, имя, username и язык.

## 24. Решение проблем

| Симптом | Что проверить |
|---|---|
| Сервис не стартует: «Неверная конфигурация окружения» | В логе перечислены переменные с ошибками (раздел 7). |
| Vercel: сборка падает за 10–20 секунд | Откройте деплой → Build Logs. «В репозитории не хватает файлов» — загрузите проект целиком или укажите Root Directory (раздел 14). |
| Vercel: `INIT_FAILED` на `/health` | В ответе указано, какой переменной не хватает. После добавления переменных — Redeploy. |
| Vercel: «Миграции не применились» | Подключите базу (Storage → Neon) и сделайте Redeploy. |
| Бот молчит | `getWebhookInfo` (раздел 15). Локально должно быть `BOT_MODE=polling`. Токен не отозван в BotFather? |
| Кнопки открывают пустую страницу | `MINI_APP_URL` должен быть **https** и совпадать с адресом сервиса. Выполнен ли `npm run build`? |
| В Mini App «Откройте магазин из Telegram» | Магазин открыт в обычном браузере или истёк `INIT_DATA_MAX_AGE` — откройте заново из бота. |
| Нет админ-панели | Ваш ID точно в `ADMIN_TELEGRAM_ID`? Напишите боту `/start`, затем `/admin`. |
| Не приходят уведомления | Клиент мог заблокировать бота или отключить уведомления в профиле; в ⚙️ Настройках проверьте переключатели уведомлений. |
| Не видны фото | Фото хранятся в Telegram. Если токен бота сменили на другого бота, старые фото недоступны — загрузите заново (✏️ Изменить → 📸 Фото). |
| Ошибка миграции | `npx prisma migrate status` в `apps/server`. Для новой БД — `npm run db:migrate`. |
| Render засыпает | Нужен платный план web-сервиса (раздел 14). |
| `Cannot find Query Engine` | Выполните `npm run db:generate` — клиент должен быть сгенерирован с `engineType = "client"`. |
